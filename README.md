# Помощник ЖКХ

Статус: требования и алгоритмы согласованы в разговоре с пользователем 02.10.2026. Приложение пока не реализовано.

## Назначение

Помогать пользователю готовить показания для личного кабинета расчётного центра, разбирать ежемесячные квитанции, сравнивать расходы и проверять начисления. Русский интерфейс для компьютера и телефона, крупные поля и понятные объяснения.

## Согласованные требования

Источник этого раздела: ответы пользователя в разговоре 02.10.2026.

- Пять действующих приборов: холодная и горячая вода на кухне, холодная и горячая вода в ванной, один электросчётчик.
- Показания каждого водосчётчика передаются отдельно.
- Ввод вручную и по фотографии, в том числе смешанный способ.
- Любые распознанные цифры пользователь проверяет и исправляет перед сохранением.
- В первой версии пользователь сам переносит значения в кабинет. Автоматическая передача — будущий этап.
- После передачи пользователь отмечает «Передано», сохраняются точные значения и дата.
- Поддерживаются фото и PDF квитанций, несколько страниц и отдельные квитанции разных поставщиков.
- Хранится история квитанций, показаний и оплат.
- При расхождении помощник объясняет его, уточняет данные вопросами по одному. Решение об обращении принимается совместно с пользователем.
- Обращение не формируется автоматически как обвинение и не отправляется без отдельного решения.
- Предусмотреть настраиваемые напоминания о показаниях и оплате; даты и способ уведомления ещё не выбраны.

## Смена электросчётчика

Пользователь сообщил, что с октября 2026 начисления переходят на один тариф. На фотографии акта предварительно прочитаны дата 07.09.2026, модель «Нартіс И100», начальное показание 0,007 кВт·ч, отметка об одноставочном тарифе.

Эти сведения не должны автоматически становиться подтверждёнными данными: перед импортом пользователь сверяет оригинал. Дата установки и дата применения тарифа хранятся отдельно. Каждый прибор имеет собственную историю. Разность показаний разных приборов не вычисляется. Для переходного периода нужны конечные показания старого прибора и сведения о фактически учтённых объёмах.

## Ежемесячный процесс

1. Выбрать месяц и дату снятия.
2. Внести показание для каждого действующего прибора или загрузить фото.
3. Показать распознанные значения рядом с оригиналом. Не угадывать нечитаемые цифры.
4. Пользователь подтверждает значения.
5. Рассчитать расход: новое подтверждённое показание минус предыдущая подтверждённая точка того же прибора. Если базы нет, запросить её, не считать её нулём.
6. Если показание уменьшилось, уточнить замену прибора, ошибку ввода или оборот счётчика. Не сохранять отрицательный расход как нормальный.
7. Экран «Для передачи»: место установки, вид ресурса, номер прибора, накопленное показание, кнопка копирования. Передаётся показание, а не вычисленный расход.
8. Пользователь переносит данные в кабинет и отмечает передачу.
9. После получения квитанции загрузить её, проверить распознавание, выполнить доступные проверки.
10. Обсудить найденные расхождения.

## Разбор квитанции

Сначала определить расчётный месяц, поставщика, услуги и единицы измерения. Отдельно извлекать объём, тариф, текущее начисление, коэффициенты, перерасчёт, снижение, долг/переплату, платежи, пени и итог к оплате. Не смешивать эти поля.

Несколько фото одного документа объединяются, повторные страницы не суммируются повторно. Отдельные квитанции разных получателей остаются отдельными документами.

Все поля имеют ссылку на исходную страницу, способ получения и статус проверки. Пустое или неразборчивое значение не равно нулю. Фото исходного документа хранится отдельно от кода.

## Проверки

### Арифметика

Выполнять программно с десятичной арифметикой. Проверять произведения и суммы с учётом структуры строки и правила округления. Не применять формулу «объём × тариф» безусловно к любому виду услуги. Не объявлять расхождение из-за скрытой точности объёма подтверждённой ошибкой без уточнения.

### Показания и расход

Сверять расчётные периоды, приборы и принятые кабинетом значения. Даты снятия могут не совпадать с календарными границами месяца. Разница между расходом по записям и квитанцией требует проверки периода и основания начисления.

### Тарифы и основания начисления

Для каждого правила нужны источник, документ, пункт/страница, дата действия, поставщик и применимость к дому. Тариф из самой квитанции не является независимым подтверждением его правильности.

Содержание жилья, коммунальные ресурсы, содержание общего имущества, капремонт и отходы проверяются отдельными правилами. Если расчёт требует общедомовых показаний, площадей или решения собственников, перечислить недостающие данные.

Рост расходов сам по себе не подтверждает ошибку. Причину нельзя выдумывать. Проверка законности требует актуальных официальных документов за проверяемый период.

### Статусы результата

- «Проверено по имеющимся данным» — указать, что именно проверено.
- «Есть расхождение» — показать исходные данные, формулу и разницу.
- «Нужны данные» — указать недостающие документы или значения.
- «Нужно проверить распознавание» — расчёт не выполняется по неподтверждённым полям.

Не выдавать общий статус «всё правильно», когда выполнена только арифметическая проверка.

## Объяснение проблемы

Карточка расхождения содержит услугу и период, значение квитанции, ожидаемое значение при известных условиях, формулу, источники, границы проверки и один следующий вопрос. Возможные причины обозначаются как версии для проверки. После ответа пользователя обновить вывод. Подготовить черновик обращения только по его решению.

## Данные и хранение

Сущности: профиль помещения, приборы, события замены/поверки, показания, подтверждения передачи, квитанции и строки, оплаты, документы-основания, результаты проверки и обсуждения.

Реальные адреса, номера квартир, ФИО, лицевые счета, номера приборов, квитанции и акты не включать в исходный код и GitHub. Примеры и тесты только синтетические. Профиль помещения пользователь заполняет локально.

Предусмотреть резервный экспорт и восстановление данных. Доступ с телефона и синхронизация истории между устройствами требуют отдельного выбора способа хранения: адаптивный интерфейс сам по себе синхронизации не обеспечивает.

## Этапы реализации

1. Каркас интерфейса, ручной ввод пяти приборов, история, расчёт расхода, экран передачи, резервный экспорт.
2. Загрузка документов и проверяемый ввод строк квитанции, арифметические проверки.
3. Реальное распознавание фото/PDF с подтверждением пользователем. Не заменять распознавание демонстрационными ответами.
4. Проверка тарифов и оснований по подтверждённым документам, обсуждение расхождений.
5. Доступ с телефона, выбранная синхронизация и уведомления.
6. Автоматизация кабинета после отдельного согласования.

Выбор технического стека, хранилища и распознавания ещё не выполнен. Не обещать бесплатное облачное распознавание или доступ к кабинету без проверки.

## Проверка перед выпуском

Проверить суммирование двух водосчётчиков одного ресурса, раздельные накопленные значения для передачи, запятую как десятичный разделитель, отсутствие исходного показания, замену прибора, повторные фото, отрицательный перерасчёт, долг/переплату, округления и сохранность данных после перезапуска.

Текущее состояние: создана документация; рабочей версии, распознавания и проверки тарифов пока нет.
