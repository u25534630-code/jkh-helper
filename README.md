# Помощник ЖКХ

Статус: требования и алгоритмы согласованы с пользователем 02.10.2026. Приложение реализовано как локальный помощник для подготовки данных и сверки по квитанциям.

## Назначение

Помогать пользователю готовить показания для личного кабинета расчётного центра, разбирать ежемесячные квитанции, сравнивать расходы и проверять начисления. Русский интерфейс для компьютера и телефона, крупные поля и понятные объяснения.

## Согласованные требования

- Пять действующих приборов: холодная и горячая вода на кухне, холодная и горячая вода в ванной, один электросчётчик.
- Показания каждого водосчётчика передаются отдельно.
- Ввод вручную и по фотографии, в том числе смешанный способ.
- Любые распознанные цифры пользователь проверяет и исправляет перед сохранением.
- В первой версии пользователь сам переносит значения в кабинет. Автоматическая передача — будущий этап.
- После передачи пользователь отмечает «Передано», сохраняются точные значения и дата.
- Поддерживаются фото и PDF квитанций, несколько страниц и отдельные квитанции разных поставщиков.
- Хранится история квитанций, показаний и оплат.
- При расхождении помощник объясняет его, уточняет данные вопросами по одному. Решение об обращении принимается совместно с пользователем.
- Обращение не формируется автоматически как обвинение и не отправляется без отдельного решения.
- Предусмотреть настраиваемые напоминания о показаниях и оплате; даты и способ уведомления ещё не выбраны.

## Смена электросчётчика

Пользователь сообщил, что с октября 2026 начисления переходят на один тариф. На фотографии акта предварительно прочитаны дата 07.09.2026, модель «Нартіс И100», начальное показание 0,007 кВт·ч, отметка об одноставочном тарифе.

Эти сведения не должны автоматически становиться подтверждёнными данными: перед импортом пользователь сверяет оригинал. Дата установки и дата применения тарифа хранятся отдельно. Каждый прибор имеет собственную историю. Разность показаний разных приборов не вычисляется. Для переходного периода нужны конечные показания старого прибора и сведения о фактически учтённых объёмах.

## Ежемесячный процесс

1. Выбрать месяц и дату снятия.
2. Внести показание для каждого действующего прибора или загрузить фото.
3. Показать распознанные значения рядом с оригиналом. Не угадывать нечитаемые цифры.
4. Пользователь подтверждает значения.
5. Рассчитать расход: новое подтверждённое показание минус предыдущая подтверждённая точка того же прибора. Если базы нет, запросить её, не считать её нулём.
6. Если показание уменьшилось, уточнить замену прибора, ошибку ввода или оборот счётчика. Не сохранять отрицательный расход как нормальный.
7. Экран «Для передачи»: место установки, вид ресурса, номер прибора, накопленное показание, кнопка копирования. Передаётся показание, а не вычисленный расход.
8. Пользователь переносит данные в кабинет и отмечает передачу.
9. После получения квитанции загрузить её, проверить распознавание, выполнить доступные проверки.
10. Обсудить найденные расхождения.

## Технические ограничения

- Данные хранятся локально в браузере, без внешнего облака.
- Источник документа хранится отдельно от кода.
- Пустые и неразборчивые значения не равны нулю.
- Поля хранятся раздельно, с привязкой к странице, способу получения и статусу проверки.
- Повторные страницы одного документа не суммируются повторно.
- Разные получатели остаются отдельными документами.
